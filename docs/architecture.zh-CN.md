## 当前基线

```text
Mosaico 屏幕 / 触摸
          │
          ▼
      app_airboat_ui ── 只读快照 ──► 显示
          │
          ▼
       有界命令队列
          │
          ▼
   app_motor_control（单所有者，10ms）
          │
          ▼
    app_motor_safety（纯 C 状态机）
          │
          └──► app_motor_output_gate（已通过主机测试，阶段 4 接入）
                              │
                              └──► 后续 app_motor_drv8833 ──► DRV8833 ──► 电机

   app_imu（BMI270 所有者） ──► 同步只读快照
```

`main` 只负责组装模块和保存生命周期。界面只提交请求，不直接驱动 GPIO；电机任务拥有安全状态；IMU 任务独占 BMI270 并发布快照。因此，电机上电前就能在电脑上验证同一套安全逻辑。

## 安全约定

- 启动为 `DISARMED`；ARM 会清掉旧命令。
- 命令范围为 `-1000..1000`，250ms 后过期并回到 `DISARMED`。
- E-STOP 锁存；CLEAR 回到 `DISARMED`，之后必须重新 ARM。
- 换向前先保持 `0/0` 至少 50ms。
- 普通请求 FIFO 容量 8；DISARM 和 E-STOP 走优先槽并清空 FIFO。
- `app_motor_output_gate` 只有在已 ARM、命令新鲜、快照一致且单桥安全时才允许输出。

软件 E-STOP 是状态切换；台架测试仍要保留随手可断开的电机电池物理断电点。

## 设备与更新边界

```text
主机工具 → 当前 Mosaico 发现 → 显式设备身份
        → 实时状态 / inventory → 选择更新流程
```

每次更新前核对当前发现结果、设备身份、启动会话、模式、版本、能力和布局。历史 COM 号只能作为线索。普通模式运行应用，Vibe Mode 提供保留更新链路，ROM 下载模式只用于恢复边界。

引导脚本固定 Mosaico 工作区提交 `1872fd88c01d7807556d01fd2a19864e40a307c9`，再把本仓库的应用源码复制进去构建和运行模拟器。

## 阶段 4 适配器

材料包和 DRV8833 到货后：

1. 记录驱动板封装、电机电流、电池电压、插头和线束能力；
2. 运行 `scripts/check-arrival.py`，解决所有 `pending` 与 `incompatible`；
3. 增加 `app_motor_drv8833`，由电机所有者任务在安全状态更新后统一拥有 GPIO/LEDC；
4. GPIO 先输出低电平，STBY 保持关闭，先应用 `0/0` 再唤醒驱动桥；
5. 拆桨、限流，只测一台电机；通过后再映射另外两路。

Interaction 模块当前占用 H1 规划的六路控制信号，首轮动力测试要在断电后取下它；摄像头等引脚稳定后再接回。

## 浮力与感知边界

首个艇体使用一个主气囊和左右独立侧囊，共用承力框架。分别记录每个气囊和完整悬挂体的质量与净升力。吊舱通风位置的 BMP581 可提供环境气压和相对高度趋势；它不测地面距离，也不测气囊内压，漏气检测另行设计。
